# Editing Page Content (Markdown)

Most page text lives in `content/*.md` and is compiled into the matching
`*.html` page by `scripts/build-content.mjs`. You can edit all page text
without touching HTML.

## How it works

- Every `content/<page>.md` with a matching `<page>.html` in the repo root is
  rendered and injected between the `<!-- JOG-CONTENT-START -->` and
  `<!-- JOG-CONTENT-END -->` markers in that page (one marker pair per page).
- If no matching `.html` exists, the page is created on the fly from
  `scripts/templates/page.html`.
- Header/footer are injected separately by `scripts/layout.mjs` from
  `partials/header.html` / `partials/footer.html`.
- After editing a markdown file, rebuild with:

  ```bash
  npm run content   # build-content.mjs + layout.mjs
  npm run build     # content + layout + fetch-sermons.mjs
  ```

  Local preview: `python3 -m http.server 8126` (browse `/about-us.html`).

## Two render modes

The first line of a markdown file selects the renderer.

### Standard mode (default)

Used by: connect, journey-classes, kids-min, discipleship, mens-ministry,
service-teams, spanish, womens-ministry, youth-group.

| Syntax | Renders as |
| --- | --- |
| `> verse text` then `> {cite} **Ref (VER)** https://www.blueletterbible.org/...` | Featured Scripture verse (`blockquote.jog-verse` with open-book icon) |
| `## Heading` | `section.jog-section` with `.jog-section-heading` |
| `::full` before `##` | Adds `.jog-section-full` modifier |
| `### Heading` | `.jog-service-card` (sections made only of `###` groups become a 2-column `.jog-service-grid`) |
| `- item` | `.jog-list` |
| `![alt](src)` (consecutive) | `.jog-photo-grid` |
| `::gallery <dir>` | Photo grid of every image in `<dir>` (sorted by name; empty folder renders nothing) |
| `::cta <href> <label>` | Centered `.jog-cta` button, e.g. `::cta connect Get Connected` |
| `::ministry <heading>` + `- [name](href)` list | `.jog-ministry` tile grid (Connect page) |
| plain paragraph | `.jog-lead` |

Standard mode has **no `h1`** — only `##`/`###` headings.

### Editorial mode

First line: `<!-- mode: editorial -->`. Used by: 404, about-us,
connection-card, event-facility-request, nextstep, privacy, sermon-archive.

| Syntax | Renders as |
| --- | --- |
| `::kicker <text>` | Small uppercase eyebrow before the next heading |
| `# Heading` / `## Heading` | `h1` / `h2` |
| `---` | Ornamental horizontal-rule block |
| `::lead <text>` | Drop-cap lead paragraph |
| `::quote <text>` + `::attrib <name>` | Pull quote with attribution |
| `::beliefs` + `- **Title.** text` lines | Newspaper creed entries (`ul.about-beliefs`; each item becomes `h3.about-belief-title` + paragraph) |
| `::address` + lines until a blank line | Postal address paragraph, lines joined with `<br>` |
| `- item` | `.jog-list` |
| plain line | `<p>` |
| `::staff` block | Staff card (see below) |

`::staff` front-matter fields, then bio paragraphs until the next `::staff`:

```
::staff
img: assets/img/vendor/<file>.jpg
role: Lead Pastor
name: Kurtis Strunk
email: kurtis@journeyofgrace.church
quote: “…”
attrib: — Kurtis

Bio paragraph one.
Bio paragraph two.
::staff
```

### Both modes

- **`::verse-rotation`** — followed by two or more `>` Scripture blockquotes
  (blank-line separated, each with an optional `{cite}` line) renders **one**
  of them, rotating per build day so every new site generation features a
  different verse. Used by the 404 "lost and found" page.

### Inline formatting (both modes)

- `**bold**`, `*italic*`
- `[label](href)` — links starting with `https?` or `mailto` automatically get
  `target="_blank" rel="noopener"`

All text is HTML-escaped (`& < > "` become entities), so raw HTML such as
`<br>` in markdown will display literally — use `::address` for addresses and
separate paragraphs elsewhere.

## Pages that are NOT markdown-driven

- **visit.html / plan-your-visit.html** — bespoke card layouts, Leaflet map,
  and forms that the renderer cannot reproduce.
- **index.html** — full-bleed video hero, intentionally footer-less.
- **sermons.html / events.html** — regenerated by `scripts/fetch-sermons.mjs`
  (YouTube) and `scripts/fetch-events.mjs` (Planning Center) via the
  "Refresh Sermons & Deploy" GitHub Actions workflow and the server-side cron
  job (`scripts/server-refresh.sh`); do not hand-edit.
- **404.html** — only the verse region is markdown-driven (via `content/404.md`).
